# 04_DATABASE_DOCUMENTATION

## Overview
MongoDB is used via Mongoose. Each collection is defined in `backend/src/models`.

| Collection | Model | Purpose |
|------------|-------|----------|
| users | User | System users (admin, organiser, staff, auditor, attendee). |
| companies | Company | Organizations that own events. |
| events | Event | Event definition, schedule, venue, zones. |
| orders | Order | Buyer orders, payment status, total amount. |
| tickets | Ticket | Individual ticket slots, status, QR code, assignment. |
| attendees | Attendee | Guest information linked to tickets. |
| paymentsubmissions | PaymentSubmission | Payment gateway submissions and verification. |
| zones | Zone | Access zones within an event. |
| zonelogs | ZoneLog | Logs of zone entry attempts. |
| entrylogs | EntryLog | Logs of event entry attempts. |
| auditlogs | AuditLog | System audit trail for admin actions. |
| requestlogs | RequestLog | HTTP request logs. |
| systemlogs | SystemLog | General system logs. |
| notifications | Notification | In‑app notifications. |
| shortlinks | ShortLink | Short URLs for event pages. |
| sponsors | Sponsor | Event sponsors. |
| systemconfigs | SystemConfig | Global configuration key/value pairs. |
| userdevices | UserDevice | Registered devices for push notifications. |
| bankaccounts | BankAccount | Bank account details for payouts. |
| rfidtags | RfidTag | Registered RFID tags linked to attendees/events. |

### Example Model Definition (Ticket)
```javascript
const ticketSchema = new mongoose.Schema({
  event: { type: mongoose.Schema.Types.ObjectId, ref: 'Event', required: true },
  order: { type: mongoose.Schema.Types.ObjectId, ref: 'Order', required: true },
  attendee: { type: mongoose.Schema.Types.ObjectId, ref: 'Attendee' },
  categoryName: { type: String, required: true },
  allowedZones: [{ type: String }],
  price: { type: Number, default: 0 },
  slotIndex: { type: Number, required: true },
  status: { type: String, enum: ['PENDING','PENDING_VERIFICATION','ASSIGNED','INVITED','CONFIRMED','CANCELLED','RESERVED','SOLD'], default: 'PENDING' },
  // … other fields …
}, { timestamps: true });
```

*All models follow a similar pattern with timestamps and appropriate references.*

### Attendee Schema Additions (RFID)
- `rfidTag` (String, index) – The assigned RFID tag unique identifier for the attendee.
- A sparse unique compound index `{ event: 1, rfidTag: 1 }` ensures that an RFID tag can be reused across different events, but remains unique within a single event.

*Note: Access control and scan methods (QR/RFID) are logged dynamically via `EntryLog` and `ZoneLog` collections rather than persisting state directly on the Attendee model.*
